# Google OAuth Setup Skill (v1)

This is a **base** skill. It manages the full OAuth2 credential lifecycle for Google APIs: detect expiry → refresh via refresh_token → if no valid refresh_token exists, initiate the PKCE auth URL flow → exchange authorization code for tokens → save credentials to disk. Domain-agnostic — any Google API consumer (YouTube, Calendar, Sheets, Drive, Gmail) reuses this.

***

## 1. Scope & Intent

- **In scope**: OAuth2 PKCE lifecycle for Google installed/native apps. Reads `client_secrets.json`, reads/writes credential cache, refreshes expired tokens, initiates browser-based auth when no refresh_token exists. Supports both `oauth2client` (legacy) and `google-auth` (modern) credential formats.
- **Out of scope**:
    - API-specific operations (uploading, querying, mutating).
    - Choosing which Google API scope to request (caller supplies scopes).
    - Managing service-account credentials (JWT-based auth).
    - Any non-Google OAuth2 provider.

***

## 3. Protocol

### 3.1 Step 1 — Verify Credential State

Given a `client_secrets.json` path and an optional credential cache path, classify the current state:

| Cache exists? | Access token valid? | Refresh token exists? | Action |
|---|---|---|---|
| Yes | Yes | Any | Use cached token directly |
| Yes | No (expired) | Yes | Refresh via `refresh_token` grant |
| Yes | No (expired) | No / expired | Initiate full PKCE flow |
| No | N/A | N/A | Initiate full PKCE flow |

### 3.2 Step 2a — Refresh Token

```bash
python3 .agents/skills/google-oauth-setup/scripts/oauth-token-refresh.py \
  --client-secrets <path> \
  --credentials <path> \
  --output <path>
```

Reads the existing credential cache, exchanges the `refresh_token` for a new `access_token` via `POST https://oauth2.googleapis.com/token`, and writes the updated cache.

### 3.3 Step 2b — Full PKCE Auth (First-Time Setup)

When no valid refresh_token exists, initiate the browser-based PKCE flow:

```bash
python3 .agents/skills/google-oauth-setup/scripts/oauth-setup.py \
  --client-secrets <path> \
  --scopes "https://www.googleapis.com/auth/youtube https://www.googleapis.com/auth/youtube.upload" \
  --output <path>
```

The script:
1. Generates a PKCE `code_verifier` (random 64-byte URL-safe token) and `code_challenge` (SHA-256 hash, base64url-encoded).
2. Prints an authorization URL for the user to visit in their browser.
3. Reads the authorization code (pasted by the user).
4. Exchanges the code for tokens via `POST https://oauth2.googleapis.com/token`.
5. Saves `access_token`, `refresh_token`, `client_id`, `client_secret`, `scopes` to the output file.
6. Exits 0 on success.

#### 3.3.1 Portability Note (web client type)

If the `client_secrets.json` is of type `"web"` (not `"installed"`), Google's OAuth server rejects `urn:ietf:wg:oauth:2.0:oob` as the redirect URI. Web-type clients MUST use their registered `redirect_uris` (typically `http://localhost:8080/oauth2callback`) and start a local HTTP server to receive the code. Use an `"installed"`-type client secret for this OAuth setup script.

### 3.4 Step 3 — Verify

```bash
# Confirm credential file is valid JSON with required fields
python3 -c "
import json
with open('<credentials-file>') as f:
    c = json.load(f)
assert c.get('access_token'), 'Missing access_token'
```

## 4. Script Reference

### 4.1 `scripts/oauth-setup.py`

Full PKCE setup flow. Usage:

```
python3 .agents/skills/google-oauth-setup/scripts/oauth-setup.py \
  --client-secrets <path> \
  --scopes <scope1> [<scope2> ...] \
  --output <path>
```

Arguments:
- `--client-secrets` — Path to Google Cloud OAuth client JSON (`{"installed":{...}}`).
- `--scopes` — One or more Google API scopes (e.g. `https://www.googleapis.com/auth/youtube`).
- `--output` — Path to write the credential cache JSON.

The script:
1. Loads the client secrets file.
2. Generates PKCE challenge pair (code_verifier + SHA-256 code_challenge).
3. Constructs and prints the Google OAuth authorization URL.
4. Reads the authorization code from stdin.
5. Exchanges the code for `access_token` + `refresh_token`.
6. Writes all fields to the output file.

### 4.2 `scripts/oauth-token-refresh.py`

Refresh an expired access token without user interaction. Usage:

```
python3 .agents/skills/google-oauth-setup/scripts/oauth-token-refresh.py \
  --client-secrets <path> \
  --credentials <path> \
  --output <path>
```

Arguments:
- `--client-secrets` — Path to Google Cloud OAuth client JSON.
- `--credentials` — Path to existing credential cache JSON (must contain `refresh_token`).
- `--output` — Path to write the refreshed credential cache.

The script:
1. Loads the client secrets and existing credentials.
2. Calls `POST https://oauth2.googleapis.com/token` with `grant_type=refresh_token`.
3. Writes the new `access_token` (preserving `refresh_token`).
4. Exits 0 on success, 1 on `invalid_grant` (refresh token expired — run full PKCE flow).

***

## 5. Edge Cases

- **`invalid_grant` on refresh**: The refresh token has expired (typically after 6 months of inactivity) or was revoked. The agent MUST fall back to the full PKCE flow (§3.3).
- **`redirect_uri_mismatch` on web client**: A `"web"`-type client cannot use `urn:ietf:wg:oauth:2.0:oob`. The agent MUST inform the user to either (a) create an `"installed"`-type client in Google Cloud Console, or (b) use a tool that handles local HTTP server OAuth (e.g. `youtubeuploader`).
- **No `refresh_token` in response**: Google only issues a `refresh_token` on the first authorization when `access_type=offline` AND `prompt=consent` are set. The script enforces both parameters. If missing, re-run with `prompt=consent`.

***

## 6. Prohibited Actions

- The agent MUST NOT hardcode OAuth client secrets or tokens in `SKILL.md` or any markdown file.
- The agent MUST NOT embed full script source in markdown — scripts live in `scripts/` and are referenced by relative links.
- The agent MUST NOT skip the PKCE verifier/challenge generation — non-PKCE (`authorization_code` grant without `code_verifier`) is rejected by Google for new clients.
