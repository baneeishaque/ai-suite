3. Web Research: CRA-to-Vite Migration Best Practices (2025-2026)
3.1 Why Migrate
- CRA is officially deprecated (React team, Feb 2025). No security patches since 2023.
- Performance gains: Cold dev server: 30-60s CRA vs 2-5s Vite. HMR: 1-3s vs <100ms.
- Build times: 2-5x faster with Vite (esbuild dev + Rollup prod).
- Smaller bundle sizes due to better tree-shaking from Rollup.
3.2 Recommended Vite Plugins for CRA Parity
Plugin	Purpose
@vitejs/plugin-react	JSX transform, React Fast Refresh (HMR), Babel integration
vite-tsconfig-paths	Reads tsconfig.json paths aliases automatically
vite-plugin-svgr	SVG imports as React components (?react suffix)
vite-plugin-pwa	Service worker + PWA (replaces CRA's workbox integration)
@vitejs/plugin-legacy	Legacy browser support via @babel/preset-env + Terser
vite-plugin-checker	TypeScript type checking in dev (Vite doesn't type-check by default)
vite-plugin-html	HTML template injection for %PUBLIC_URL%-like patterns

3.5 Migration Strategies
Full Cutover (Recommended)
 1. Create backup branch
 2. Uninstall react-scripts, install vite + @vitejs/plugin-react
 3. Create vite.config.ts
 4. Move public/index.html to root, remove %PUBLIC_URL%, add script tag
 5. Update env vars (REACT_APP_ -> VITE_, process.env -> import.meta.env)
 6. Update tsconfig.json (moduleResolution: "bundler")
 7. Update SVG imports
 8. Update package.json scripts
 9. Remove CRA-only deps (react-scripts, sass-loader, @types/webpack-env, @testing-library/* if moving to Vitest)
10. Set up Vitest (or configure Jest standalone)
11. Test thoroughly
Time estimate: 30-90 minutes for most projects.
Gradual (react-app-rewired / craco)
- Not recommended. Vite and react-scripts cannot coexist. The migration is all-or-nothing at the build-tool level.
- Some teams do a multi-branch approach: migrate on a branch, QA in parallel, then switch.
Fresh Scaffold + Copy Source
- An alternative strategy: scaffold a new Vite project, then copy src/ and public/ over.
- Cleaner but more work if there are build config customizations.
3.6 Testing Migration (Jest -> Vitest)
Vitest is the recommended path because it shares Vite's config, has instant startup, and a Jest-compatible API.
Key changes:
- jest.fn() -> vi.fn()
- jest.mock() -> vi.mock()
- jest.spyOn() -> vi.spyOn()
- beforeEach/describe/it/expect all work identically
- Add test: { globals: true, environment: 'jsdom', setupFiles: './src/setupTests.ts' } to vite.config.ts or create vitest.config.ts
