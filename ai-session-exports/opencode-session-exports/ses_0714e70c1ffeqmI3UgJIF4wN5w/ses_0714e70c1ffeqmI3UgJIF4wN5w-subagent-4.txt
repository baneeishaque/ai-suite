Vite Bundle Analysis Tools: Complete Research
1. rollup-plugin-visualizer (The Industry Standard)
Package: rollup-plugin-visualizer (npm)
Repository: https://github.com/btd/rollup-plugin-visualizer
Stars: 2,398 | Weekly Downloads: ~2.5M+ | Latest Version: 5.14.0 (Jul 2026)
Maintainer: @btd (very active, 606 commits)
Since Vite uses Rollup under the hood for production builds, this Rollup plugin is the de facto standard for Vite bundle analysis.
How to install and configure:
npm install --save-dev rollup-plugin-visualizer
In vite.config.ts:
import { defineConfig, type PluginOption } from 'vite';
import { visualizer } from 'rollup-plugin-visualizer';

export default defineConfig({
  plugins: [
    // ... other plugins
    visualizer({
      open: true,               // auto-open browser
      template: 'treemap',      // 'sunburst', 'treemap', 'network', 'raw-data', 'list', 'flamegraph'
      gzipSize: true,           // show gzip-compressed sizes
      brotliSize: true,         // show brotli-compressed sizes
      filename: 'stats.html',   // output filename
    }) as PluginOption,
  ],
});
Output formats (templates):
- treemap -- interactive rectangular hierarchical view (default)
- sunburst -- circular/radial view, good for spotting large chunks
- flamegraph -- top-down version of sunburst
- network -- force-directed graph answering "why is this included?"
- raw-data -- JSON output for programmatic use
- list -- YAML file, good to commit to track changes over time
- markdown -- Markdown summary with tables
Dev vs Build mode:
- Build mode only (Rollup hooks run during vite build)
- Does not work in vite dev (no bundle is created in dev mode)
Key features:
- gzipSize and brotliSize calculation
- Sourcemap-based size calculation (more accurate for minified code)
- Include/exclude filter patterns (picomatch)
- CLI tool to merge multiple stats JSON files
- emitFile option for Rollup-managed output (useful for SvelteKit multi-build)
- Node.js >= 22 required (latest version)
Known limitations:
- The network view can be noisy; highly connected nodes (react, tslib) dominate
- No CSS file analysis in the report
- Must be placed last in the plugins array for correct size reporting
- Requires Node.js >= 22 (newer constraint)
2. vite-bundle-visualizer (CLI Wrapper)
Package: vite-bundle-visualizer (npm)
Repository: https://github.com/KusStar/vite-bundle-visualizer
Stars: 454 | Weekly Downloads: ~184K | Latest Version: 1.2.1 (May 2024 -- stale)
This is a thin CLI wrapper around rollup-plugin-visualizer that lets you run analysis without modifying vite.config.ts.
How to configure:
# One-shot analysis (no config needed):
npx vite-bundle-visualizer

# With options:
npx vite-bundle-visualizer -t sunburst -o ./reports/stats.html --open true
Available templates:
- treemap (default)
- sunburst
- network
- raw-data (JSON)
- list (YAML)
Dev vs Build mode:
- Runs a build internally, so build mode only
Known limitations:
- Stale/unmaintained -- last release May 2024, appears abandoned
- The README itself says: "In most scenarios you shouldn't need this library, the recommended solution is to add rollup-plugin-visualizer directly to your vite configuration."
- No gzip/brotli size calculation from CLI
- Thin wrapper with no added features over the base plugin
3. vite-bundle-analyzer
Package: vite-bundle-analyzer (npm)
Repository: https://github.com/nonzzz/vite-bundle-analyzer
Stars: 459 | Weekly Downloads: ~236K | Latest Version: 1.3.9 (Jul 2026 -- very active)
Maintainer: @nonzzz (very active, 81 releases)
A standalone Vite/Rollup/Rolldown bundle analyzer with a Foamtree visualization (similar to webpack-bundle-analyzer).
How to install and configure:
npm install vite-bundle-analyzer -D
In vite.config.ts:
import { defineConfig } from 'vite';
import { analyzer } from 'vite-bundle-analyzer';

export default defineConfig({
  plugins: [
    analyzer({
      analyzerMode: 'static',    // 'server' | 'static' | 'json' | function
      fileName: 'stats',         // output filename (no ext)
      reportTitle: 'Bundle Analyzer',
      defaultSizes: 'gzip',      // 'stat' | 'gzip' | 'brotli'
      openAnalyzer: true,
      analyzerPort: 8888,
      summary: true,             // show console summary
    }),
  ],
});
Output format:
- Interactive FoamTree treemap (the same library used by webpack-bundle-analyzer)
- No sunburst, network, or flamegraph views
- analyzerMode: 'server' -- launches a local dev server with the report
- analyzerMode: 'static' -- generates a standalone HTML file
- analyzerMode: 'json' -- outputs raw JSON data
- analyzerMode: function -- custom callback
Dev vs Build mode:
- Build mode only (Rollup plugin hooks)
- Has a built-in server mode (analyzerMode: 'server') that serves the report on a port
Key features:
- Very active development (81 releases, latest Jul 2026)
- Supports Vite, Rollup, and Rolldown (experimental) via adapters
- Gzip/brotli compression analysis
- Console summary output during build
- Minimal zero-config setup
- Customizable server port with 'auto' fallback
- enabled flag for conditional analysis
Known limitations:
- Only one visualization type: FoamTree treemap (no sunburst, network, or flamegraph)
- "Vite enables minification by default. The parsed size may appear larger than actual size because bundle info from Rollup isn't compressed."
- Rolldown support is experimental
- Smaller community than rollup-plugin-visualizer
4. Sonda (Universal Analyzer -- Rising Star)
Package: sonda (npm)
Repository: https://github.com/filipsobol/sonda
Stars: 772 | Weekly Downloads: ~157K | Latest Version: 0.13.1 (Jul 2026 -- very active)
A newer, universal bundle analyzer that works with 6 bundlers (Vite, Rollup, Rolldown, esbuild, webpack, Rspack) and 5+ frameworks (Next.js, Nuxt, Astro, SvelteKit, Angular).
How to install and configure:

export default defineConfig({
  build: {
    sourcemap: true,      // required by Sonda
  },
  plugins: [
    Sonda(),
  ],
});
Output format:
- Interactive treemap graph
- Compression sizes (gzip, brotli)
- Dependency tree (answer "why is this included?")
- Deep view with "inspect code" capability
- JSON report for CI/automation
Key features:
- Accuracy: analyzes final source maps after tree-shaking and minification for the most accurate sizes
- Multi-bundler: single tool works across Vite, Rollup, webpack, esbuild, Rspack, Rolldown
- Duplicate package detection: automatically finds and highlights duplicates
- Code inspection: see the actual code included in each module
- Issue detection: flags common problems like duplicated dependencies
- CI-friendly: JSON report output for automation
Dev vs Build mode:
- Build mode only (requires source maps from production build)
Known limitations:
- Requires sourcemap: true in Vite build config (slightly increases build time)
- Currently does NOT include CSS files in Vite reports (Vite doesn't generate source maps for CSS)
- Relatively new/young (v0.x), API may still change
- Smaller community than rollup-plugin-visualizer
- Must add sonda/vite as a separate plugin, not a simple Rollup adapter

RECOMMENDATION for a Large CRA-to-Vite Migration
Primary Recommendation: rollup-plugin-visualizer
For a CRA project with antd, ag-grid, material-react-table, react, redux toolkit, and many other large dependencies, I recommend using rollup-plugin-visualizer as the primary tool, with this configuration pattern:
// vite.config.ts
import { defineConfig, type PluginOption } from 'vite';
import react from '@vitejs/plugin-react';
import { visualizer } from 'rollup-plugin-visualizer';

export default defineConfig({
  plugins: [
    react(),
    // Conditionally enable visualizer via env var
    process.env.ANALYZE === 'true' && visualizer({
      open: true,
      template: 'treemap',         // Start with treemap for big-picture view
      gzipSize: true,
      brotliSize: true,
      filename: 'dist/stats.html',
    }) as PluginOption,
  ].filter(Boolean),
});
Then run: ANALYZE=true npm run build
Why rollup-plugin-visualizer wins for your use case:
1. Most mature and proven -- 2,398 stars, 606 commits, 9 years of development
2. Largest set of visualization types -- treemap for big picture, sunburst for dependency clusters, network for "why is this included?" tracing
3. gzip and brotli sizes essential for evaluating the real-world impact of large deps like antd and ag-grid
4. Vite team itself recommends it -- the official Vite migration guide from webpack maps BundleAnalyzerPlugin to rollup-plugin-visualizer
5. YAML output can be committed to track bundle changes over time during the migration
6. Conditional enablement via env var is a well-established pattern (no config changes needed for normal builds)
Secondary Recommendation (alongside): sonda
Use Sonda as a supplementary tool for deeper analysis:
npm install -D sonda
// vite.config.ts (add alongside visualizer)
import Sonda from 'sonda/vite';

export default defineConfig({
  build: {
    sourcemap: true,
  },
  plugins: [
    // ... other plugins
    Sonda(),                     // adds duplicate detection & code inspection
  ],
});
Sonda's duplicate dependency detection is invaluable for a CRA migration where you may have multiple versions of the same library from different transitive dependencies.
Not Recommended
- vite-bundle-visualizer -- unmaintained since May 2024, its own README tells you to use rollup-plugin-visualizer directly
- vite-bundle-explorer -- too new and unproven (1 star) for a production migration
- rollup-plugin-bundle-stats -- too specialized; use Sonda instead for duplicate detection
Migration-Specific Workflow
For the CRA-to-Vite migration specifically:
1. Phase 1 (baseline): Use rollup-plugin-visualizer with treemap to see the current bundle composition with Vite
2. Phase 2 (duplicate hunt): Add Sonda to detect duplicated packages across your many deps
3. Phase 3 (optimization): Use the network graph from rollup-plugin-visualizer to trace why specific large modules (antd, ag-grid) are bundled and consider code splitting
4. Phase 4 (regression guard): Commit the YAML output of rollup-plugin-visualizer to track bundle size changes across migration steps
